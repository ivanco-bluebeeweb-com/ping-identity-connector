# Ping Identity Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md`. Целевой пользователь: IT-администратор
или security engineer, впервые открывающий приложение.

## 1. Credential type
PingOne Worker Application: `client_id` + `client_secret` + `environment_id` (UUID) +
`region` (NA/EU/AP/CA).

## 2. Идеальный флоу (без ограничений SDK)
1. **Region-picker первым полем** — так как base URL целиком зависит от региона
   (`api.pingone.com`, `api.pingone.eu`, `api.pingone.asia`, `api.pingone.ca`),
   выбор региона должен визуально предшествовать полям client_id/secret, а не быть
   спрятанным полем среди прочих.
2. **Ссылка на точное место в консоли** — "Environment > Applications > Add
   Application > Worker" с копируемым чеклистом ролей (Identity Data Admin минимум),
   так как PingOne требует явного назначения ролей Worker-приложению при создании,
   иначе коннектор получит 403 на большинство вызовов.
3. **Проверка перед сохранением** — реальный обмен client_id/secret на токен через
   `/as/token` и один тестовый вызов (например `GET /environments/{id}`), чтобы
   подтвердить одновременно и креды, и env_id, и регион.
4. **После успеха — environment health snapshot** — заблокированные/отключённые
   пользователи, отключённые приложения, всплеск неудачных попыток входа из Activities,
   чтобы пользователь сразу увидел живые данные.
5. **Ошибки — конкретные, не generic 401/403** — если регион указан неверно (частая
   ошибка: домен региона предполагает другой data residency), явно подсказать
   "проверьте регион окружения", а не просто "unauthorized".
6. **Явное предупреждение перед delete_user** — в PingOne это НЕОБРАТИМОЕ удаление
   (в отличие от Okta, где deactivate — soft-delete с 30-дневным окном), поэтому
   именно здесь нужно двухшаговое подтверждение с явным текстом "нельзя отменить",
   не общей формулировкой.
7. **Multi-environment** — переключатель между несколькими подключёнными PingOne
   окружениями (например, sandbox vs production одного клиента), с явным лейблом.

## 3. Разница с реализацией сейчас
Реализация ограничена наличными примитивами SDK (см. `UI_COMPONENT_PLAN.md` §0):
region выбирается через `ui.Select` (не кастомный picker с флагами регионов),
ссылка на консоль — обычный `ui.Button` с `on_click=ui.Open(url)` на публичную
документацию Ping (не deep-link в конкретный tenant, т.к. tenant URL нам неизвестен
до подключения). Двухшаговое подтверждение для delete_user реализовано через
`ui.Button` с `confirm=` (native SDK confirm-dialog), текст явно говорит "нельзя
отменить" — это покрывает идеал разумно близко.
